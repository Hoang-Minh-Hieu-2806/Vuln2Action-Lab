## Sampling procedure

1. The authoritative case list is `splits.json["human_eval_20"]`, generated by
   `src/vuln2action/connectors/reproduction.py:make_splits`. Do **not** replace it
   with `docs/human-evaluation/cases.json`; that file only records the source
   `PAPER_HUMAN_EVAL_CVES` and may be padded deterministically.
2. If `splits.json` is absent, request it from the dataset owner. If it cannot be
   obtained, rebuild the dataset with the documented seed and then extract the
   same field. Do not hand-pick cases.
3. Keep exactly 20 CVE ids. If a replacement is ever necessary, it must be drawn
   from the same deterministic split procedure and the deviation recorded.
4. Generate the 20 workflows with the chosen provider and checkpoint id. Record
   provider, checkpoint, decoding settings, dataset SHA-256 and `splits.json`
   SHA-256. The reviewer only sees the workflow text.
5. Reference material stays in a separate section and is opened only after a
   case is scored.

## Data collection format

One JSONL file, one object per scored case. Empty fields are left `null`; never
pre-fill a numeric score.

```json
{
  "case_id": 1,
  "cve_id": "<from splits.json human_eval_20>",
  "provider": "<rule_based | t5>",
  "checkpoint_id": null,
  "dataset_sha256": null,
  "splits_sha256": null,
  "workflow": "<generated workflow text>",
  "scores": {"correctness": null, "completeness": null, "clarity": null},
  "flags": {"correctness": null, "completeness": null, "clarity": null},
  "comment": null,
  "reviewer_role": "advisor, 1 person",
  "reviewed_at": null
}
```

A flagged criterion has a `null` numeric score and must be excluded from means.
Aggregate only numeric scores, keep two decimals, and report flagged counts.
